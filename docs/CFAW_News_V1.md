## 0. 执行摘要（先读）

### 0.1 一句话产品定义

CFAW News 是面向 AI 开发者的个人技术情报 Agent：从新闻、官方材料、论文与开源项目发现重要进展，结合用户背景和已有信息，生成**覆盖广、重点分明、证据透明**的情报简报，在用户下次主动打开时补齐值得知道的变化。

### 0.2 不做什么

不以用户每日活跃为目标；不默认发送邮件、系统通知或应用外提醒；不替用户安装、部署、修改代码或决策；不将通用 Deep Research、自动规划、长期研究任务、多 Agent、公开多租户、复杂日程管理纳入首版关键路径；不保证覆盖全部 AI 资讯或绝对正确。

### 0.3 三层页面

1. **重点情报**：少量但有信息密度的事件，说明发生了什么、为何重要、对用户的潜在影响、关键证据、未知项。
2. **前沿速览**：更广覆盖、每条 1–2 句、揭示未证实之处，不造成阅读负担。
3. **资讯资料库**：保留可检索原始报道、原文链接与历史；并非推荐页面中的信息都被删除。

“新发现 / 有实质变化 / 之前提及”是每条情报的状态，**不是新建一个复杂的独立产品线**。

### 0.4 首个验收故事

用户 7 天未打开应用。期间某技术出现首次发布、转载、独立测试、官方更正以及替代方案。用户第 8 天打开：一眼看到仍有价值的关键事件；转载不占多个推荐位；更正提升优先级且明确原判断变化；不将曝光等同理解；没有应用外提醒；各结论能回溯当时可见的证据。

### 0.5 首轮唯一开发目标

先完成 **G0 现状审查 + G1 可回放评测数据与时间约束基线**。G1 未过门槛，暂停训练模型、复杂 UI 重做和持续自动 Agent 框架引入。

## 1. 产品需求文档 PRD

### 1.1 用户与核心场景

- 首位用户：正在开发 AI/Agent 应用、需要跟踪模型、Agent 框架、RAG/检索/评测及生产力工具的独立开发者。
- 主要任务：用有限时间理解最近真正值得知道的进展；留意平时不主动搜索但可能有用的新事物；忙碌后补上重要变化。
- 延伸用户：背景与偏好不同的 AI 开发者，评测中以明确、可审查的多个 persona 覆盖，而不推断单人结果可泛化。
- 核心矛盾：**覆盖率与阅读负担**、**新颖性与可靠性**、**时间新鲜度与长期重要性**、**个性化与信息茧房**。

### 1.2 P0 / P1 / Out-of-scope

| 等级 | 能力 | 核心验收 |
|---|---|---|
| P0 | 多源采集及来源健康 | 可确认成功/失败、来源覆盖、最新抓取时间，失败不冒充全量更新 |
| P0 | 事件级聚合及转载去重 | 10 篇同事件转载只产生 1 个推荐主项，保留多来源引用 |
| P0 | 情报二层分配 | 重点信息解释充分，潜力信息仅精华，均有依据或不确定标注 |
| P0 | 回访窗口 + 时间加权 | 1/3/7 天回访找回旧而重要的内容；近期普通消息不会天然压过重大变化 |
| P0 | 引用/事实边界 | 发布声明≠验证能力；声称与实证分开；引用可追到版本 |
| P0 | 事件级曝光去重 | 记录“纳入简报 / 实际展示 / 打开详情”不同动作；重复内容不刷屏 |
| P0 | 离线可复现评测 | 时间可见性、分组泄漏检测、种子/版本/预算记录、基线对比 |
| P1 | 显式兴趣与轻量反馈 | 有帮助/一般/不感兴趣/已了解；可撤回，不推断已掌握 |
| P1 | 源站类型扩展 | 官方 release / changelog、GitHub、论文和独立评测逐步增加 |
| P1 | 预算化补证 | 仅对有潜力的候选按工具/费用预算补官方证据 |
| ⛔ | 自主安装部署与代码调试 | V1 不做 |
| ⛔ | 通用深度研究及长期研究工作台扩张 | 不在首版关键路径；旧功能保留而不发展 |
| ⛔ | 主动 App 外消息推送 | 与用户明确偏好相反 |

### 1.3 交互与默认行为

- **首次使用**：可以不设置兴趣直接进入默认 AI 情报；允许一句话设定兴趣，相关预测标识为推断，用户可纠正。
- **进入首页**：展示 `覆盖窗口`、`来源健康`、`重点情报`、`前沿速览`、`资料库入口`；信息不足不凑条数。
- **打开情报卡**：展示主张、置信边界、来源、原文链接、首次发现/实质更新时间及为何相关。
- **用户反馈**：显式 `有帮助`、`一般`、`不感兴趣`、`已了解`，默认未反馈；反馈影响推荐策略，不改写外部事实。
- **再次访问**：以“从上次访问以来的重要变化”为主；不把上次访问视为已阅读，不把详情打开视为已理解。
- **来源断线/进程停机**：显示最后成功采集与缺口，不称“没有重要变化”。
- **行为边界**：后台在授权和运行条件下主动采集整理；用户打开应用才阅读；用户不需要按提示行动。

### 1.4 关键业务规则与非功能需求

1. 所有可发布情报有稳定事件 ID、可用时间、输入文档版本与可还原引用；模型解释不冒充来源事实。
2. 官方发布事实、厂商性能宣称、独立复现、社区观点是不同证据类别；单一分数不替代来源性质。
3. 文档不可穿越时间：任何 t 时刻的回放不得读取 t 之后首次可观察到的页面、快照、标签或统计。
4. 同一事件的内容改写不产生新的事件曝光；实质变化可以重新升权，但必须说明增量依据。
5. 旧 `run`、决定、已确认应用内日程不可因迁移被删除或覆盖；当前 `expected_version`、引用快照、取消/失效防发布、批准幂等契约持续有效。
6. 对外来源访问保持 SSRF、重定向、DNS、TLS、资源大小/并发限制；不得把采集材料里的指令当作系统指令。
7. 版权：优先保存许可范围内的摘要/必要片段与来源链接；别把“公开可访问”误写成“允许全文转载”。
8. 单用户本地使用为 V1 验收环境；网络公开部署前必须单独完成认证、权限、隔离和安全审查。

## 3. G1：数据集总体设计

### 3.1 明确定义任务，避免“数据集不知道评什么”

- **T1：时间一致的事件识别**：给定时点 t 可见文档，输出相互独立的事件集合以及文档→事件归属；辨别“同一事件转载”与“相关但不同事件”。
- **T2：情报价值与展示层级**：给定 persona、已有背景及 t 时刻可见候选，给每个事件标注 `重点 / 速览 / 资料库 / 暂不推荐`，附价值维度和证据状态。
- **T3：更新与回访**：给定前次简报记录、用户曝光状态、事件历史以及 t 时刻可见新材料，标注 `首次发现 / 实质更新 / 非实质重复 / 应暂缓` 与事件级优先顺序。
- **T4：证据真实性与引用**：识别事件主张的来源性质、支持/反驳/未验证关系，以及用户可核对的时序版本片段。
- **T5（次阶段）**：在预算内选择证据补充动作；G1 只定义可离线回放的工具动作和基线，不运行开放 Web Agent。

### 3.2 数据规模与拆分：区分开发、校准与最终留出

**G1-a（契约验证）**：5 条时间轨迹 × 3–6 个时间点（总计 15–30 个时间状态）。建议每条 6–12 份文档版本，共约 30–60 版本，仅作为**开发与标注一致性检查**，不能据此宣称泛化。

**G1-b（算法开发）**：扩至 20–30 条轨迹，尽量覆盖 100–200 个时间状态、不同子领域/语言/来源性质；用于调参和开发比较，具体数量以独立事件家族数及预算确定，不是 KPI。

**G1-c（独立评估，G5 冻结）**：建议后续独立收集至少 20 个不同事件家族的留出轨迹（前期规划值），标注团队/验证流程与训练调参隔离；满足样本代表性后再决定最终规模。不可把 5 条开发轨迹反复改写成“独立测试”。

五条开发轨迹应各包含一个对照挑战：①早期发布→传播转载→独立验证；②官方更正/撤回；③高热度低实证；④已有事件关键约束改变；⑤跨领域弱相关但对具体 persona 有潜在价值。每条同时出现至少一个 `no_change` 观察点和一个对时间排序不利的重要旧事件。

### 3.3 数据目录与不可变版本

```text
evals/
  intelligence_v1/
    README.md                 # 数据来源、许可、任务、运行方法
    DATA_CARD.md              # 范围、缺陷、筛选偏差、用途边界
    schema/                   # JSON Schema / Pydantic 或 Python dataclass 契约
      documents.schema.json
      events.schema.json
      labels.schema.json
      snapshots.schema.json
    manifests/
      dataset_manifest.json    # 数据集版本、SHA256、冻结时间、切分、标签规范
      source_registry.json    # 来源类型、许可、可靠性边界
    raw/                      # 原始可分发材料或合法引用/哈希，必要时只保留外链
    versions/documents.jsonl  # 一行一个原始可见的不可变文档版本
    events/events.jsonl       # 稳定事件身份与关联文档版本
    claims/claims.jsonl       # 事实或技术主张、证据关系
    personas/personas.jsonl   # 用户目标与约束；敏感真实数据不进入公开集
    timelines/steps.jsonl     # 每个回放时点的可见性及上一轮简报
    labels/gold.jsonl         # 事件-用户-时点的人工金标签
    labels/annotations.jsonl  # 各标注者原始判断
    labels/adjudications.jsonl# 仲裁与分歧原因
    splits/families.jsonl     # 按事件家族和衍生来源锁定切分
    predictions/              # 基线/实验模型输出，不污染 gold
    reports/                  # 指标、误差、成本、覆盖窗口
```

采用 JSONL 是为便于 diffs、逐条验证与流式重放；原始材料应按许可采取“全文/摘要/外链+哈希”的保守方案。冻结后的版本只追加，不原地修改。任何 gold 修订写新 `annotation_version` 并记录理由。

### 3.4 数据核心实体与字段

**DocumentVersion（文档版本）**：`doc_version_id`, `document_id`, `canonical_url`, `source_id`, `source_type` (`official|paper|repository|independent_test|media|community|other`), `content_kind` (`publisher_text|feed_summary|archive_authored|quoted_excerpt`), `language`, `title`, `text_excerpt`, `content_sha256`, `published_at`（可空）, `published_time_confidence`, `first_seen_at`, `observed_at`, `available_at`, `supersedes_version_id`, `redistribution_rights`, `record_origin` (`real|synthetic`), `provenance_uri`, `event_family_id`. `available_at` **必须**是能够证明此版本已经可供系统使用的最早时间，不允许简单沿用网页自称的发布时间。

**EventGroup（事件）**：`event_id`, `family_id`, `canonical_subject`, `event_type` (`release|capability|benchmark|safety|correction|research|tool|other`), `first_observed_at`, `document_version_ids`, `related_event_ids`, `status` (`open|updated|corrected|withdrawn|archived`), `identity_note`. 标注 `same_event` 不能把“同一家公司发布两个模型”自动合并。

**Claim（最小主张）**：`claim_id`, `event_id`, `claim_text`, `asserted_by`, `evidence_refs` (`doc_version_id`, 可选 `paragraph_id`), `claim_type` (`release_fact|capability_claim|measured_result|constraint|risk|other`), `evidence_direction` (`supports|refutes|mentions|unknown`), `verification_state` (`source_attributed|independently_supported|disputed|unverified|retracted`), `valid_as_of`. 不允许仅由引用存在而自动判定 `supports`。

**Persona**：`persona_id`, `domain_interests`, `current_goals`, `hard_constraints`, `knowledge_known`, `attention_budget_seconds`, `exploration_preference`, `locale`, `persona_origin`（`constructed|consented_real`）。不存敏感身份详情；人格化偏好和背景有明确版本与当时可见时间。

**ReplayStep**：`timeline_id`, `step_id`, `as_of`, `visible_doc_version_ids`, `persona_version_id`, `previous_delivery_id`, `attention_budget_seconds`, `expected_event_ids`, `time_window_start`, `time_window_end`. `visible_doc_version_ids` 可由严格过滤生成，但**回放必须保存实际解析结果**供复现。

**GoldLabel**：`label_id`, `timeline_id`, `step_id`, `persona_id`, `event_id`, `relevance` 0–3, `potential_value` 0–3, `evidence_quality` 0–3, `novelty_to_persona` 0–3, `material_change` (`new|meaningful_update|no_change|correction|withdrawal|insufficient`), `tier` (`focus|radar|archive|hold`), `rationale`, `supporting_doc_version_ids`, `uncertainty`, `annotator_id`, `annotation_version`, `adjudication_status`。多维度分数是标签，不应直接暗示已经训练好的权重。

**Delivery/Exposure（G3 时落地）**：`delivery_id`, `generated_at`, `as_of`, `user_id_local`, `item_id`, `event_id`, `included_at`, `rendered_at`（可空，只有客户端确认展示才记）, `opened_at`（可空）, `ack_at`（可空）, `feedback`（可空）。G1 可以用固定历史模拟，不能在离线基线里调用真实用户数据库。

### 3.5 时间模型：四道“未来不可见”门禁

1. 候选纳入条件：`available_at <= replay.as_of`，且来源受该次 replay 的允许范围限制。
2. 文档升级：旧版不可在回放中被较晚版本覆盖；`supersedes` 不能使未来更正版出现在旧时间。
3. Persona 历史：只允许当时已经显式给出的用户兴趣、可观察的展示/点击/反馈；未来点击不可回灌过去。
4. 文本与标签：过去的模型预测不能借用未来标注理由、最终知名度、当前网页内容或事后描述。Gold 只用于评测，不进入预测 prompt。

保存 `published_at`、`first_seen_at`、`observed_at` 与 `available_at` 的不同含义；同一博客发布时间早于采集时间，不意味着过去可以使用今天才取得的正文。所有 timestamp 使用带 `Z`/offset 的 ISO 8601，入库存 UTC，UI 按用户时区显示。未知时间标注 `null`，不能随便设为采集日期并当原始发表时间。

### 3.6 事件家族、来源派生关系、去重挑战

- `document_id` 是同一原文的稳定身份；`doc_version_id` 是一次不可变的内容状态；`event_id` 是具体进展/公告；`family_id` 将同一项目/论文/衍生报道/技术演化连接以防 split 泄漏。
- `exact_duplicate`：规范 URL + 内容 hash 一致；`syndicated`：不同站点转载同一信息；`same_event_different_evidence`：同一事件的独立测试/更正，必须保留信息增量；`related_distinct_event`：相关但不应合并。
- Source 独立性不可仅以 hostname 判断：同一新闻稿被两个媒体转载仍是同一上游来源，独立测试需追溯方法与独立产生的数据。

## 4. G1：标注体系（AI 开发默认，真人研究可选）

### 4.1 标注顺序

1. 验证原始来源与时序版本完整性（无法证实时记缺失，不凭印象补写）。
2. AI 标注并复核文档与事件关系：确切重复、转载、同事件新证据、相关但独立。
3. 标注可验证主张和支持/反驳/提及关系；不把厂商声称当作第三方验证。
4. 给每个 persona × 回放时间 × 事件标注相关性、新颖性、潜在价值、证据状态、变化类型。
5. 最后决定重点/速览/资料库/暂缓；必须留一句与证据相符的解释。
6. 记录分歧，允许 AI 证据复核及裁定，明确其为开发判断；困难标签可保留 `uncertain` 和 `not_enough_context`。

### 4.2 标签量表（刻度可操作）

| 字段 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| `relevance` | 无联系 | 弱关联 | 关联当前兴趣 | 直接关联显式目标/硬约束 |
| `potential_value` | 无明确价值 | 有趣但用途不明 | 合理潜力 | 可能明显改善现有任务/知识判断 |
| `novelty_to_persona` | 既知无增量 | 轻微补充 | 明确新事实 | 新能力/重大约束/重要纠正 |
| `evidence_quality` | 来源不可追 | 仅单源自述 | 有可核对原始材料或有限独立验证 | 多份实质独立的直接证据且范围清晰 |

**展示层级操作规则**：

- `focus`：影响大或与明确任务强相关，且有足够可核对材料；若含重大风险/更正，即使证据还不充分也可以作为“风险/待核实重要信息”突出呈现，绝不夸大确定性。
- `radar`：信息真实存在，可能有启发，但应用收益未得到验证；1–2 句话 + 来源与不确定性。
- `archive`：一般更新、重复且无实质新信息、价值低但保留检索。
- `hold`：来源无法验证、明显错误、不可合法展示；可保存必要审计元数据但不公开输出断言。

优先级依赖 persona 与时间，不能只给整篇文档一个永久标签；例如对开发者的重要安全补丁，对普通学习者的价值可能不同。标注者无法确定时必须保留争议与仲裁原因。

### 4.3 变化分类与易混点

| 标签 | 示例（假设） | 不应该怎么标 |
|---|---|---|
| `new` | 首次可见的模型发布 | 旧公告多一家转载不能算新 |
| `meaningful_update` | 新的可靠独立测试改变能力认知 | 新标题/阅读量增加通常不够 |
| `no_change` | 五篇媒体复制同一发布稿 | 不能因候选集合变化就认定事实变化 |
| `correction` | 官方更正支持平台或许可证 | 更正不能自动当撤回全部功能 |
| `withdrawal` | 项目正式撤销一项承诺 | 本轮未检索到旧文章不能算撤回 |
| `insufficient` | 时间/来源不足以判断更新 | 不等于“没有变化” |

标注时区分 `novelty_to_world`（事件确实新）与 `novelty_to_persona`（用户此前是否可能接触）；不能凭系统推荐过就当用户已经理解。

### 4.4 一致性/仲裁机制

- DEV-01～05 默认由 AI 完成初标、复核和裁定，单个 AI 即可，不以第二名真人为 G1-a 开发门槛。AI 结果与真人研究结果分开，规则见 `docs/plans/G1_AI_DEVELOPMENT_RULES.md`。
- 事件配对使用成对 precision/recall 与双标一致率；有序 0–3 标签使用**加权 Cohen's κ**，分层类别使用 κ 或 Krippendorff α，报告样本数和置信区间。
- 每类主要标签的目标建议：初始一致性 ≥0.70 作为需观察阈值，开发路径低于阈值时复核争议并记录局限；真人研究路径低于阈值须修订规范并重新标注；κ 在极端类别比例下会异常，必须同时公布混淆矩阵和原始一致率。
- 仲裁员不得看到模型测试输出；所有更改保留 `annotator_id`、修改时间、理由、标签版本。

### 4.5 五条开发轨迹的测试设计

| 轨迹 | 信息演进 | 主要困难 | 应有行为 |
|---|---|---|---|
| DEV-01 | 产品发布→3 转载→独立验证→官方补充 | 重复、来源独立性 | 首次速览，转载不重复，验证后视影响升级 |
| DEV-02 | 框架版本发布→兼容性宣称→官方更正 | 更正及时性 | 根据更正修改结论，并解释旧限制变化 |
| DEV-03 | 高热度项目→营销转发→有限测试 | 热度≠证据 | 简短介绍并标明待核实，不无依据升为重大突破 |
| DEV-04 | 旧技术已介绍→6 天后出现关键安全问题 | 回访与风险 | 第 8 天仍纳入重点，不被时间衰减压掉 |
| DEV-05 | 不直接属于 Agent 的方法→与 persona 的检索问题相关 | 意外发现/跨域 | 至少在速览保留合理探索空间 |

五条轨迹是**数据构建工作项**，目前没有实际采集完成；不可将上表当真实事件数据。

## 5. G1：算法基线与对照矩阵

### 5.1 公平比较原则

- 固定相同 replay step 的时间可见候选、语种、来源集合、persona 与阅读预算。
- 基线时间排序、BM25、Dense、Hybrid/RRF、通用 LLM 摘要和新方案应使用相同输入候选范围；若某算法多调用补证工具，分设工具预算组并额外报告成本，不能与不用工具的基线称严格同预算。
- 相同 generator（精确模型 revision、temperature、max tokens、prompt 版本、工具调用上限），必要时将“只比较排序”实验与“最终生成简报”实验拆开。
- 数据切分按 family 与时间；同一事件派生的 persona 或转载不得跨训练/测试。
- 每次运行固定 seed、模型身份、依赖指纹、Git SHA 与 dataset_manifest SHA，并保留逐步预测 JSONL。

### 5.2 从低成本到强基线的梯队

| ID | 基线 | 输入信号 | G1 状态 | 意义 |
|---|---|---|---|---|
| B0 | 时间倒序 | 有证据的可见时间 | 必做 | 普通最新新闻流 |
| B1 | 现有 BM25 | persona 兴趣/目标生成的词法查询 | 必做（复用后核验） | 当前工程对照 |
| B2 | BM25 + 事件精确去重 | B1 + canonical/hash 或已标注事件组（分 oracle/预测两种） | 必做 | 去重本身收益 |
| B3 | B2 + 简单时间加权 | 实质变化时间/首次可见时间 | 必做 | 时间与回访收益 |
| B4 | B3 + 明确曝光规则 | 已呈现无更新降权 | 必做 | 个性化历史增量的最小消融 |
| B5 | 通用 embedding 检索 | 固定预训练模型 | G2/G5 | 语义强基线 |
| B6 | BM25+Dense/RRF | 相同候选 | G2/G5 | 混合检索 |
| B7 | 通用 CrossEncoder | 固定预训练模型 | G5 | 排序强基线 |
| B8 | 通用 LLM 摘要 + 排序 | 固定 prompt 和预算 | G2/G5 | 生成型竞争方案 |
| P1 | 事件+证据+用户历史价值排序 | 新增数据结构与特征 | G3/G5 | 待证实的研究改进 |

**重大注意**：B2 如果直接使用 gold 事件组，只能称 oracle upper bound；真实预测实验必须由模型/规则自己聚类，不能偷偷使用金标。G1 的强制可运行集为 B0–B4；其他基线提前定义但不将其写成 G1 完成条件。

### 5.3 可解释的初始排序策略（实验假设，非已验证算法）

在不使用未来信息的前提下，先对事件生成特征：

- `I`：重要度/技术影响的当时估计；
- `R`：用户目标相关性；
- `N`：对用户的事实新颖度；
- `E`：证据可核实程度；
- `Δ`：相较上次实际呈现的实质变化；
- `T`：**非线性时效**（最近有实质变化的旧事件保留得分）；
- `D`：无增量的曝光次数/转载惩罚；
- `X`：探索多样性奖金（限定比例，避免淹没重要信息）。

预注册一个非常简单的实验启发式：`score = 2*I + 2*R + 2*N + E + 2*Δ + T - 2*D + X`，对各 0–3/标准化特征进行尺度统一，**禁止把此公式当训练成果或最优权重**。实际权重只在开发集调整，并与逐项消融比较；安全更正或重要撤回可使用有证据支持的特殊优先规则，但必须单独统计误报。

阅读预算以 `max_focus=3`、`max_radar=12`、`max_estimated_read_seconds=420` 作为**首次实验配置**，不是产品永久限制；分别评测 180/420/900 秒预算。速览信息可有折叠分页，不能通过无限增加雷达条目作弊。

### 5.4 指标定义与计算单位

- **事件级 Recall@K**：当时真实“重要且可见”的 event 中，前 K 个去重事件命中的比例；K 固定或由读时预算映射。开发路径使用冻结的开发期望，真人研究路径使用独立真人 gold，分别报告。
- **nDCG@K**：多级 `relevance/potential_value` 构造的 graded relevance；公式和权重在指标配置中冻结。
- **ImportantMissRate**：在限定阅读预算内漏掉的重点情报事件数 / gold 重点事件数；与 Recall 一起报告。
- **DuplicateExposureRate**：同次简报里，重复展示同一 event（或同一事实）的条目数 / 总展示条目数；另报跨次无新事实重复率。
- **MaterialChangePrecision/Recall/F1**：预测“实质更新”对人工标注的 precision/recall/F1；更正与撤回分别报告。
- **EvidenceSupportPrecision**：随机人工抽样的陈述中，被引用文档片段语义支持的比例；单纯引用 ID 有效性另报。
- **IndependenceErrorRate**：转载被错误当作独立佐证的案例占比。
- **RevisitCoverage@budget**：1/3/7 天回访窗口内仍然重要的事件被及时呈现比例。
- **Latency/Cost**：每 100 文档的离线处理时长、单份简报模型 Token/费用、来源错误率；未知 token 记缺失，不能作 0。
- **Human comprehension（G4 以后）**：有限时间内用户正确回忆关键信息的比例，以及主观有用性；不得由候选系统的 LLM 自评替代。

所有比值报告分母和事件数量，对同一 family 的相关样本使用 family-level bootstrap 给置信区间，避免把大量转载当独立样本。

## 6. G1：验收测试和发布门禁

### 6.1 单元测试清单（至少 20 个具名案例）

| ID | 场景 | 预期 |
|---|---|---|
| T01 | `available_at` 晚于 `as_of` | 不可见，不进入任何索引或 prompt |
| T02 | 文章标称早发布、采集晚 | 在采集可见之前不可使用 |
| T03 | 正文 10/20 更正、回放 10/15 | 只能取旧文档版本 |
| T04 | 同 URL、内容 hash 相同 | 版本去重，不新建意义重复 |
| T05 | 同 URL 内容 hash 改变 | 生成新版本，旧版可回放 |
| T06 | 不同 URL 同一上游稿 | 聚为同一事件，不算两份独立佐证 |
| T07 | 同项目两项独立公告 | 不误合并 |
| T08 | 官方声称性能提升 | 只能标为 claimed，非 independent_verified |
| T09 | 独立测试限定环境 | 保存适用范围，不泛化所有环境 |
| T10 | 无候选或源站故障 | 空结果/覆盖缺口，不能称世界无变化 |
| T11 | 用户上次访问但未浏览该事件 | 不计已理解，也不计已明确已读 |
| T12 | 同事件上次曾展示且无增量 | 大幅降权，不重复霸屏 |
| T13 | 同事件出现有效更正 | 可以重新进入重点位置 |
| T14 | 六天前重大更新 vs 今天普通新闻 | 重大更新不被纯时间压没 |
| T15 | 同 event 三篇报道 | 最终简报只产生一个主展示位 |
| T16 | 模型输出不存在的引用段落 | 拒绝/显式失败，不接受伪证据 |
| T17 | 引用定位存在、内容不支持结论 | 语义支持评测失败而非自动通过 |
| T18 | 评分相同的多条结果 | 由稳定 tie-breaker 保证可复现 |
| T19 | 只改变 persona 关键约束 | 价值层级可变，事实真值不变 |
| T20 | 回放中注入未来用户反馈 | 显式拒绝 |
| T21 | 停机期间未采集 | 覆盖缺口可见，不称已持续监控 |
| T22 | 新评测运行修改 gold 文件 | manifest hash 校验失败 |
| T23 | 旧同事件数据跨 train/test | split 验证阻止或报错 |
| T24 | 多次对同一输入运行 B0–B4 | 排名与 JSONL 完全一致 |
| T25 | 历史运行/日程/决定在迁移前后 | 数量和关联一致，旧接口可读 |
| T26 | 人工构造和真实数据混合 | 每条 provenance 明确，无伪装真实 |

### 6.2 G1-a 最低门槛（硬门槛与研究目标分开）

**硬门槛，不达标禁止转 G2**：

1. 5 条轨迹、每条 3–6 步；有文档版本、事件、persona、标签、完整 manifest 和来源/合成标识。
2. 时间可见性负例测试 T01–T03/T20 **100% 通过**，严禁未来泄漏。
3. schema 校验、唯一 ID、完整引用、版本内容哈希、family split 检查 **100% 通过**。
4. B0–B4 均能逐步运行；相同输入/种子/版本可得到相同 JSONL 和指标汇总。
5. 开发标签完整、时序与来源可追溯；AI 可完成初标、复核和裁定，保存原稿与修订记录。真人双标为可选研究门槛，不再阻塞 G1-a 开发验收或 G2 离线准入。
6. 每一步输出召回、nDCG、重复率、更新识别、时间窗口覆盖、成本；指标允许 NaN/undefined，但分母为 0 时不得伪造 0%/100%。
7. 不影响现有产品历史证据、版本、取消、用户决定和日程记录；迁移如尚未发生则标记 N/A，不报“通过”。

**研究观察目标，不作为必须提升的硬门槛**：B3/B4 比 B1 在回访覆盖和重复降低上更好。G1 样本过小、标签主观，允许没有提升；不能为凑提升修改金标。

### 6.3 人工验收脚本：七天回访

**固定脚本**：D0 推荐项目 X 的“早期潜力”并记录 included；D1–D3 三篇转载；D4 独立测试部分证实能力；D6 官方更正某系统限制；D7 出现新替代方案 Y；D8 用户主动进入简报。

**必须观察**：X 只占一个主项；D1–D3 不能使 X 变成三次“全新”事件；D4 的验证范围明确；D6 进入“有实质变化”且展示修订依据；Y 可以作为首次新机会；用户没点开 X 不当作已理解；D8 内容依旧包含重要的 D4/D6，不能仅以 24 小时截断；来源失败和未来信息检查可复现；无应用外通知。

**反事实测试**：删除 D6 更正，再跑相同输入，系统不应声称发生更正；替换 persona 为对 X 无直接工作需求的人，情报排序与价值解释可以不同，但对 X 技术事实的归纳不能改变。

## 8. 开发路线：Epic / Story / 交付物 / 依赖 / 门槛

### G0：现状审查、环境锁定（建议 3–5 个有效工作日；估算，不是承诺）

- G0-01 锁定 HEAD/依赖：SHA、系统环境、package lock、数据库 schema、历史基线结果。
- G0-02 复现全套测试，记录通过/失败及失败上下文。
- G0-03 复用矩阵审查 12 个现有模块，优先数据库/采集/检索/引用/服务。
- G0-04 备份旧 SQLite，验证恢复到单进程启动状态。
- G0-05 记录无法读到的来源、许可、时间字段与不可变证据缺口。
- **交付**：`G0_REUSE_AUDIT.md`、`G0_BASELINE.json`、备份校验与风险清单。
- **进入 G1 条件**：能够运行至少基线/测试入口，或明确列出且解决阻断项；历史用户数据可恢复。

### G1：数据与基线（建议 10–20 个有效工作日）

- G1-01（任务定义）T1–T4 确定输入、输出、标签、时间语义，评测冻结规则。
- G1-02（来源合法性）挑选五个 AI 技术变化故事，登记来源、时间、许可、可再分发边界。
- G1-03（数据契约）完成 6 个 JSONL schema、ID/时间/hash 校验、数据字典。
- G1-04（版本采集）建立不可变 DocumentVersion 和时间可见性过滤器。
- G1-05（事件关系）标注 exact/转载/同事件新证据/相关独立事件。
- G1-06（标注）AI 初标 + 证据复核；先试标 1 条、修规范，再完成 5 条，真人双标可选。
- G1-07（回放）将每条轨迹拆成 3–6 个时间步，生成冻结的候选快照。
- G1-08（基线）B0 时间、B1 BM25、B2 去重、B3 时间、B4 历史曝光；明确 oracle 开关。
- G1-09（指标）事件 recall/nDCG、重复、变化 precision/recall、1/3/7 天覆盖、成本与分母。
- G1-10（自动化验收）未来泄漏、版本覆盖、split family、确定性、空集行为与七天回访验收。
- **交付**：`DATA_CARD.md`、`ANNOTATION_GUIDE.md`、JSONL 与 manifest、B0–B4 报告、replay 脚本和最小测试套件。
- **进入 G2 条件**：第 6 章硬门槛通过，不以指标“漂亮”为替代。

### G2：事件合并与证据/情报生成（建议 15–25 个有效工作日）

- 建立可预测的 `EventGroup`（先 hash+规则+embedding 可选）；区分转载、实际新证据、独立验证。
- 建立有来源约束的 `Claim` 片段关联与事实类型，记录冲突和更正。
- 创建版本化 `IntelligenceItem` 输出 schema；规则模板起步，再可选用现有模型接口生成自然语言。
- 展示 `focus` 与 `radar` 两类深度；事实不可超出引证内容，不编造实验数字。
- 做事件分组与信息忠实度人工抽检，保存具体误判案例；先离线，后接 API。
- **交付**：固定输入→稳定结构化情报，来源/版本追踪全通，事件级错误分析。

### G3：个性化与回访排序（建议 15–25 个有效工作日）

- 建立显式 persona/兴趣，弱行为只用作排序信号；实现可撤回用户反馈。
- 实现 `delivery` vs `rendered` vs `opened` 区分，时间窗口补齐和有证据的变更重新提升。
- 阅读预算分配（重点 vs 速览），探索比例试验，按 180/420/900 秒比较。
- 算法对照：B0/B1/B2/B3/B4 → P1，并进行去重、历史、证据、时间、探索因素消融。
- **交付**：回访情报排序器及用户历史策略说明，失败与成本分析。

### G4：前端接入与端到端使用（建议 10–20 个有效工作日）

- 首页三层呈现，保持原文章阅读入口；增加简报窗口、来源覆盖说明、引用详情、新发现/更新标识。
- 简单反馈、列表筛选和「已了解」显式操作，不能用任何一次被动曝光代表学习。
- 打通来源故障、离线缺口和历史保留的 UI；桌面 Web 主流程 Playwright 回归。
- 用独立于单一演示轨迹的真实技术文章持续使用，记录人工反馈与错误。
- **交付**：个人可日常使用的 V1 Beta，不声称 24/7 覆盖除非后台实测。

### G5：研究级评测与发布（建议 20–35 个有效工作日）

- 冻结独立事件家族测试集，按正式版本签名与 SHA 验证；不再依据测试结果改规则。
- 引入 Dense/Hybrid/通用 CrossEncoder/普通 LLM 摘要强基线，统一来源、预算和模型。
- 多种 persona 和 1/3/7 天条件下报告召回、增量、去重、证据支持、成本及结果方差。
- 至少做 4 项消融（去历史/去事件合并/去时序/去证据），给失败图谱。
- 独立人工审查一定样本的事实支持、潜力错判与机会漏报；报告潜在偏差和不可复现项。
- **交付**：`EXPERIMENT_CARD.md`、可重放配置、固定测试结果、复现脚本、失败分析与研究报告；若无增益，亦如实结论。

以上工日仅用于单人规划量级估算，和并行能力、真实数据获取、外部模型可用性高度相关；不作为交付期限。建议每个阶段结束时按实际样本规模重新估算后续工作量。

## 10. 风险登记与应对

| 风险 | 信号 | 处理 |
|---|---|---|
| 无法获取真实旧版本 | 网页今天内容覆盖过去 | 不把今天网页伪装成过去可见；用 Wayback/官方版本历史经许可核对，缺失则用合成轨迹并标识 |
| 信息质量标注主观 | 标注者分歧大 | 先修定义；分维度标签+仲裁，报告一致性 |
| 实验被数据泄漏污染 | 同事件转载进入 train/test | `family_id` 切分 + 文本近重复检测，冻结 manifest |
| 漏掉重要机会 | 只看高相关来源 | 增设探索池与来源覆盖统计；报告源未覆盖造成的上限 |
| 为追求召回无限扩充内容 | 读时成本飙升 | 固定 attention budget + 召回/阅读成本前沿曲线 |
| 时效权重压掉旧重大发现 | 回访出现漏报 | 引入 `last_material_change_at`、分层分布与抗强衰减对照 |
| 热度替代事实验证 | 官方宣称被标独立验证 | Claim 级来源性质，独立性标注/抽查 |
| 过度个性化 | 只重复用户喜欢的技术 | 留探索预算；对跨域样本测覆盖 |
| Agent 工具成本失控 | 每条新闻触发 LLM 搜索 | 分层预算，优先规则/缓存，对重点信息才补证 |
| 源站权利与安全 | 内容再分发/SSRF/注入 | 最小摘录+授权、隔离网络请求、原文为不可信输入 |
| UI 改造破坏旧功能 | 历史 run、决定、日程不可见 | 保留迁移与端到端回归；先 feature flag |
| 缺少真实用户反馈 | 开发样本过拟合自己 | 多 persona/事件家族留出，后续开展小规模自愿用户测试 |

## 11. DoD 总表：什么时候算 V1 成功

### 11.1 必须证明的正确性

- [ ] 无未来证据泄漏；事件分组与历史版本可回放。
- [ ] 原始文档与推荐情报可双向追踪，主张/出处分离。
- [ ] 无实质更新的报道不会重复占据推荐位；修正/撤回能够解释。
- [ ] 1/3/7 天回访能覆盖之前未见且仍有价值的关键事件。
- [ ] 来源断线或进程停止时覆盖缺口可见。
- [ ] 不发送任何非用户授权的应用外通知、不擅自执行真实行动。
- [ ] 原有历史记录、版本/取消/批准规则回归通过。

### 11.2 必须公开的研究结果（不预设一定提高）

- [ ] B0 时间、B1 BM25、B2 去重、B3 时间、B4 历史；G5 含至少 2 个更强通用检索/排序基线。
- [ ] 事件召回、重要漏报、nDCG、重复、实质变化、证据支持、用户阅读预算与成本。
- [ ] 至少 1 次冻结测试 + 多事件家族统计置信区间 + 消融 + 失败分析。
- [ ] 明确当前数据不能证明什么：时序覆盖范围、语言偏差、合成样本占比、用户画像外推、人工标签歧义。

### 11.3 第一版产品体验验收

用户忙碌七天后主动打开 CFAW News，能快速补上这段时间最值得知道的 AI 技术变化，适当接触潜力信息，读到重要信息的可查证依据，没有被一堆旧闻和重复报道淹没；至于后续研究和行动，完全由用户自主决定。

## 12. 与项目原交接文档的区别（变更决策记录 ADR）

| ADR | 原方向 | 本轮决定 | 影响 |
|---|---|---|---|
| ADR-001 | 目标检查是主要用户入口 | 个人情报简报为默认入口，Goal 变可选信号 | 需要事件+情报输出，不硬塞 Goal |
| ADR-002 | 主动研究并辅助行动 | 核心聚焦信息发现与理解，用户自行深入行动 | Deep Research 和日程降优先级 |
| ADR-003 | 持续目标研究 | 有界自主观察潜在机会；不默认增加正式研究任务 | 观察池/曝光区别于关注 Goal |
| ADR-004 | 新闻候选相关性为主 | 事件级价值、证据、时序与阅读预算 | 新标注/评测体系 |
| ADR-005 | 日常新闻流 | 时间加权的回访情报简报 | 引入时间可见性与用户曝光状态 |
| ADR-006 | 仅词法检索 + LLM 判断 | 基线保留，逐步比较语义与历史感知排序 | 先数据与评测，再主张算法增益 |
