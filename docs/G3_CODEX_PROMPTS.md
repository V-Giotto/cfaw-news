# G3 的 Codex 执行与逐 PR 审查提示词

> 本文提供可直接复制给 Codex
> 的提示词。请严格按顺序执行：先审计，再逐个实现 PR；每个 PR
> 完成后必须使用对应的独立审查提示词，审查通过并由项目所有者确认后才进入下一
> PR。
>
> **重要约束：**
> 本文件是工作流程，不是对仓库的修改授权。若项目所有者尚未批准启动
> G3，只能执行"初始审计"，不得实现代码。

## 0. 使用规则

1.  在仓库根目录运行 Codex，先阅读 `AGENTS.md`。
2.  本阶段计划以
    [`G3_IMPLEMENTATION_PLAN.md`](G3_IMPLEMENTATION_PLAN.md)
    为目标规格；同时必须遵守 V1、G2 实施计划、G2 发布说明和 G2→G3
    交接契约。
3.  一次只做一个 PR。不要把 PR1--PR5 一次性实现。
4.  实现提示词与审查提示词分开使用。审查提示词默认**只审查、不改代码**。
5.  不要仅凭 Codex 自述判定测试通过。必须检查实际命令、退出码和输出。
6.  不安装依赖、不联网、不调用真实模型、不访问付费服务，除非项目所有者另行明确批准。
7.  不修改 G1/G2 冻结数据、契约、manifest、历史验收报告或既有实验结果。
8.  不修改生产数据库、React 前端、采集流程或旧业务逻辑来绕过 G3 问题。
9.  若遇到契约冲突、字段语义不明、测试需要外部服务、范围扩张或安全/隐私决策，暂停并提出问题，不要猜。
10. 完成每个 PR
    后，报告改动文件、测试命令/退出码、工件、未解决问题和风险；不要把未运行的测试写成通过。

## 7. 最终集成与验收审查提示词（全 G3）

``` text
请对 G3 全部实现进行最终独立集成审查。只审查，不修改代码。

先阅读 AGENTS.md、G3_IMPLEMENTATION_PLAN.md、所有 PR 审查记录、G1/G2 冻结契约和最终 git diff。检查整个 G3，不只检查最近一个 PR。

请验证：
A. 架构与范围
- G3 是否是独立离线包；没有未经批准的生产 DB、React、API、采集、真实模型或新依赖集成。
- G1/G2 冻结契约、数据、manifest、报告是否无改动。
- G2 输出 -> G3 输入 -> 排名 -> 预算计划 -> 指标/工件的链路是否清楚。

B. 数据与时间正确性
- as_of 是否覆盖文档/事件版本、Persona、历史交互、coverage 和配置。
- 是否有未来信息、Gold 标签或事后结果泄漏。
- event key/revision、证据、来源独立性和不确定性是否完整保留。
- included/rendered/opened/acknowledged 是否严格区分。
- 更正、撤回、重大变化和事件合并/拆分是否有明确策略。

C. 算法与预算
- 基线与 P1 是否使用共同候选池和公平实验条件。
- B2/G2 去重贡献是否单独归因。
- P1 组件、权重、缺失值、tie-break 是否可解释且版本化。
- 预算与排名是否分离，预算是否可审计，未展示候选是否保留。
- coverage unknown 是否未被解释为“没有变化”。

D. 测试与复现
- 实际执行全部必要测试和 acceptance（如果环境允许），记录真实命令、退出码和输出。
- 核对 manifest、pin、代码/测试/配置指纹和工件哈希。
- 验证缺失/不匹配工件会导致失败。
- 检查测试是否存在过宽断言、无效 mock 或只验证实现自述的情况。

E. 结果与诚实性
- 所有指标是否有分子、分母、样本数、undefined reason。
- 合成数据和开发期望是否被正确标注。
- 是否报告负面结果、失败案例、成本、覆盖和样本局限。
- 是否避免宣称真实用户效用、生产就绪或独立研究证明。

输出：
1. P0-P3 Findings（文件/行号、触发条件、影响、建议）。
2. 测试/验收的真实执行记录；未运行项必须标明。
3. 仍然存在的工程风险和研究限制。
4. G3 总体结论：BLOCK / PASS WITH CONDITIONS / PASS。
5. 是否建议进入 G4；进入 G4 前必须完成的前置事项。
6. 明确列出 G3 不应声称已经实现的能力。

不要因为阶段计划已完成或测试数量较多就默认通过。没有足够证据时，结论应为 BLOCK 或 PASS WITH CONDITIONS。
```

## 9. 执行纪律

-   PR1 审查通过后才进入 PR2；依此类推。
-   审查发现 P0/P1 问题时先修复并复审，不得跳过。
-   如果测试环境不允许运行某项验证，写明原因和替代证据，不得伪报通过。
-   如果计划与实际 G2 契约冲突，停止并提出 ADR；不修改 G1/G2
    来消除冲突。
-   最终验收报告必须将"工程门槛通过"和"算法效果改善"分开写。

**推荐顺序：初始审计 → PR1 实现 → PR1 审查 → 修复/复审 → PR2 实现 → PR2
审查 → ... → PR5 审查 → 最终集成审查。**
