# DEV-01～05：AI 开发与验收规则

生效日期：2026-10-23。依据项目所有者本次要求，替代 DEV-01～05 原有的“必须由两名真人作答才能完成 G1-a”规定。
适用于 G1-a 开发轨迹、PR2/PR5 协作提示词和 G2 离线开发准入；不自动开始 G2。

## 1. 谁完成工作

- AI 可以完成五条轨迹的数据整理、事件归并、主张抽取、评分、引用支持判断、复核、争议裁定、开发标签及验收报告。
- 单个 AI 即可执行“初稿 → 证据复核 → 修订”流程；第二个模型、第二个会话或真人均为可选。不得因缺少第二名真人要求用户反复补交材料或停止其他开发工作。
- 不要求用户手工录入、亲自改错、代填真实收包时间或提供第二名真人身份确认。AI 可以修复自己新生成的开发记录。
- 多轮 AI 复核记为 AI 内部检查；同一会话已看过完整轨迹或参考答案时如实披露，不声称时序盲标或统计独立。

## 2. 可见材料与产物

1. 逐步读取 `as_of` 前可见的版本、persona、曝光和覆盖信息。预测输入不能读取任何参考标签或未来信息。
2. 初标、复核记录分别保存，包含执行者类型 `ai`、实际模型/会话信息（未知写未知）、规则版本、材料包 SHA、实际生成时间、理由、引用和修订差异。处理时间与合成剧本时间分开。
3. 事件关系、四维 0–3、graded relevance、tier、变化类型、occurrence/capability、scope 的语义沿用 V3；其“仅限真人录入”和“双人提交”的流程限制不适用于 AI 开发路径。
4. 无法裁定则保留 `uncertain / insufficient`。没有前后两份不同结果时，分歧和仲裁可记录为不适用，不能伪造 A/B 或分歧。
5. 数据来源 `real / synthetic` 描述材料，执行者 `ai / human` 描述标注过程，二者分开记录。AI 阅读真实材料并不会将它变成合成新闻；现有 DEV-01～05 的虚构材料仍是 synthetic。
6. AI 原稿与复核记录存入新的本地批次目录；可执行开发期望通过现有 `SyntheticExpectation` 契约写入新版本的 `fixture_expectations`，使用 `--label-source synthetic-fixture` 评测。该契约适用于当前合成轨迹，不将真实材料或 AI 结果导入人类 gold 通道。
7. 开发期望是人工或 AI 编写的测试参照；既有期望不自动改称 AI 复核成果。新增、修订标签需要保存理由、旧版本和哈希；不能看算法得分调整标签。
8. 版本、主张、原始提交和历史报告保留。更改规则或期望后另冻 dataset revision，并使用新 manifest pin 重跑有关检查。

## 3. 两种验收口径

| 项目 | `ai_development`（默认） | `human_research`（可选） |
|---|---|---|
| 用途 | DEV-01～05 契约、回放、开发比较，G2 离线开发准入 | 真人标注研究与一致性结论 |
| 真人双标 | 可选，缺失不阻塞 | 保留原有身份、独立初标、冻结、仲裁和 lineage 检查 |
| 标签 | 完整、可见、冻结的 synthetic 开发期望；与 human gold 分开 | 合规真人原始提交与 gold |
| 一致性 | 单次 AI 无 κ；多轮仅作内部诊断，低一致性列问题并复核 | 按原有双人标准处理 |
| 必需工程门槛 | 数据、时间、契约、来源、开发标签覆盖、B0–B4、复现、指标、回归与限制披露全部通过 | 原有技术门槛及真人门槛全部通过 |
| 缺少真人时 | `human_annotation_gate` 仍如实为 BLOCKED/FAIL，但不参与开发 profile 的通过判定 | 总验收未通过 |

`g1a_passed` 和 `g2_eligible` 按输出中的 `acceptance_profile` 解释；开发 profile 的 PASS 只表示可以继续离线开发。
`human_research_passed` 单独报告，不随开发 profile 放宽。技术失败、标签覆盖缺失、哈希或测试证据过期仍会阻止验收。

```powershell
python -B -m evals.intelligence_v1.acceptance --manifest <manifest.json> --manifest-sha256 <pin> --runs <fresh-runs> --checks <fresh-checks.json> --out <new-output> --profile ai_development
# 需要真人研究口径时显式选择：--profile human_research
```

规则修改本身不会把旧报告翻成 PASS，也不构成已完成五轨迹 AI 标注或已完成 G1 总验收。需在新版本下实际生成、检查和验收相应产物。

## 4. 结论边界

可以报告工程契约、固定合成样例表现、AI/开发期望下的指标与误例。AI 引用支持判断明确写为 AI 复核；程序引用定位、AI 语义判断、真人审查分别报告。
真人研究、真实用户有用性、理解测量、独立留出泛化和线上生产验证，在实际实施前保持未测，不是 DEV-01～05 的前置任务。

## 5. 旧规则的适用范围

`ANNOTATION_GUIDE.md`、`ANNOTATION_GUIDE_V2.md`、`ANNOTATION_GUIDE_V3.md` 以及旧冻结包、真人审计 CLI 和历史收口报告保留原文与哈希，供历史复现及可选真人路径使用。
其“必须真人”“AI 不可作答”“缺第二人不得进入 G2”等要求不适用于当前 AI 开发路径。当前代理执行以本规则、AGENTS.md 及已更新的 V1/G1 计划为准。
